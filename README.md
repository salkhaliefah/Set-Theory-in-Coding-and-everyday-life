                                            Set Theory in Coding and Everyday Life
Have you ever noticed that when you repeatedly watch certain types of content or frequently visit the same websites, your phone starts tailoring what you see to match your interests? For example, Netflix’s “You Might Like” section suggests movies and shows similar to what you’ve already watched. Behind those polished screens is a system that tracks user behavior and customizes recommendations accordingly. 
Before we connect this to our main point, let’s briefly touch on set theory. In mathematics, set theory is the study of sets — collections of objects (called elements) that can be analyzed, counted, and manipulated.
In the world of programming, arrays work in a similar way. They store collections of elements that can be accessed, counted (iterated through), updated, and manipulated — much like sets in set theory. However, arrays maintain the order of elements and can contain duplicates, meaning the same value can appear more than once. In contrast, sets (both in mathematics and in coding) do not allow duplicates — any repeated value is stored only once. See image Figure 1 for a visualization.

Let’s say you and your friend use the same Netflix account. You each watch different content, and Netflix collects that data to identify viewing interests. While Netflix might not realize that two people are sharing the account, it can still track what content is being watched, whether it’s by you alone or by both of you. Based on the overlap in your viewing habits, Netflix might create a “You Might Like” category that recommends movies and shows appealing to both you and your friend. Netflix may not know it’s essentially creating an intersection of you and your friend’s viewing habits — but now you do.

Another operation is Union — the set of all elements that appear in both A and B, with no duplicates. In coding, we can represent this using a set data structure, which automatically removes duplicates — similar to what we discussed earlier when comparing arrays and sets. See Figure 3.

Let’s look at a real-world example. A store has recently been remodeled to make product organization more efficient for shoppers. Before the remodel, Aisle A contained all the skincare products and Aisle B contained all the haircare products. After the remodel, to save space and make shopping easier, the store created Aisle E, which combines all the products from both Aisle A and Aisle B. This represents the union operation in set theory — combining all elements from two sets into one, without duplicates.

Throughout this paper, we’ve connected the dots between set theory, coding, and everyday life. By the end of reading this, I hope you can see the meaningful correlation between these areas. Set theory shows us that order, connection, and grouping exist in both code and life. The next time you organize, combine, or compare things in your world, think of it as your own set operation in action.
